# 雷氏产品方法论

## 核心原则

### 1. 单点切入，克制贪婪
- 资源有限时，切口越小压强越大。聚焦解决**一个**用户最迫切的需求。
- 检查问题：当前产品是否在试图解决多个问题？如果是，砍掉非核心功能。

### 2. 对"不完美"零容忍
- 极致不是天赋，是**可打磨、可训练的**习惯。
- 发现熟视无睹的丑陋细节时，必须停下来改进，而非容忍。

### 3. 口碑源于"超出预期"
- 用户觉得便宜/好用≠有口碑。只有当产品体验**超出用户原本的心理预期**时，口碑才会产生。
- 检查问题：当前方案的哪个点能让用户"哇"一声？

### 4. 快节奏迭代
- 保持对用户反馈的极速响应，参考 MIUI 周更节奏。
- 不要追求一次性完美，而是通过快速迭代逼近最优解。

## 工作流

### 阶段一：产品定义（专注）
1. 列出所有想做的功能。
2. 问：哪一个是用户**现在最痛**的刚需？
3. 砍掉其余，只保留这一个。
4. 输出：一句话产品定义 + 一个核心功能。

### 阶段二：死磕细节（极致）
1. 找到该功能中最粗糙的环节。
2. 问：这个细节的**理论最优解**是什么？
3. 持续改进直到"再努一把也没法更好"。
4. 输出：当前最粗糙环节 + 改进方案 + 改进后的预期效果。

### 阶段三：用户参与（口碑与快）
1. 让用户参与开发过程（论坛、反馈群、内测）。
2. 建立快速迭代机制（参考周更节奏）。
3. 发布时，确保有一个点**明显超出**用户预期。
4. 输出：用户参与方案 + 迭代节奏 + 超出预期的设计点。

## 边界条件

- 本 Skill 适用于**资源有限**的初创产品定义或成熟产品的体验攻坚。
- 不适用于需要铺量、覆盖全价格段的防御性产品策略。
- 当用户明确要求"快速铺量"或"覆盖尽可能多的用户"时，不应触发本 Skill。
